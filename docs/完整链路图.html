路五个路由决策点（edges.py 的条件路由）

图的骨架是这 5 组条件边 + 2 条静态边（START→supervisor、intent→supervisor）。条件边运行时才决定往哪走。

决策点路由函数条件 → 去向关键点
supervisor 之后 route_after_supervisor state 无 intent → intent_node
task_plan 有 PENDING → 按任务 agent（policy/material/workflow）
全完成 → supervisor（合成）或 governance 		任务状态机驱动：每个 Task status PENDING → COMPLETED/FAILED
policy/material 之后 route_after_specialist 先检查 error/risk → 再复用 route_after_supervisor 全部去向 异常 → error 置位 → 回 supervisor 重试（retry_count < 3）；risk=high/critical 提前进 governance
workflow 之后 route_after_workflow waiting_task_id → END（A2A 挂起）
_needs_a2a() → a2a_node
全完成 → governance 		_needs_a2a 关键词：房产/不动产/公积金… → 意图 property_service/fund_query
a2a 之后 route_after_a2a waiting_task_id → END（挂起）
有 error → supervisor（重试）
否则 → governance 		异步：send_task 后 checkpoint 落库，外部 Agent 回调 /api/a2a/callback 恢复
governance 之后 route_after_governance blocked / waiting → END
error 且 retry < 3 → supervisor
否则 → END 		安全阻断或正常结束都收口到 END；错误重试有次数上限
为什么 supervisor 是中心？所有专业 Agent 执行完都回到 supervisor 重新路由（task_plan 状态机驱动），保证任务按序执行、错误可重试、风险可提前收口。intent→supervisor 是静态回环，保证意图识别后必二次规划。

盾Runtime 安全护栏 + 三级降级链

Agent 执行由 orchestration/langgraph/runtime.py 包裹，所有外部依赖都有降级路径。

机制规则触发行为
LoopDetector 滑动窗口 6 次调用；连续 3 次相同 tool 触发 → 中断循环 → 重新规划
StepLimiter 最大执行 10 步 超过 → RuntimeExceededError → 优雅终止
Timeout 单 Agent 60s（agent_timeout） 超过 → RuntimeTimeoutError
Guardrail 输入护栏前置 + 输出护栏后置 注入/敏感词 → 阻断（不消耗 Token）；PII → 自动脱敏
层级降级对象降级行为
L1 基础设施PostgreSQL / Redis / Milvus内存模式 / 无缓存 / BM25 关键词检索
L2 模型层LLM API / BERT规则模板回答 / 关键词匹配 fallback
L3 协议层MCP Server / A2A Connectorstub 模板回答 / 本地 Mock Agent
